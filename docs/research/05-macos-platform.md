# Platform Constraints and Media-Format Realities on macOS (Apple Silicon, macOS 15/26)

Research date: 2026-09-08. Scope: an AI-driven video editor with a browser UI plus a local macOS helper process running ffmpeg and ML models. Inputs: iPhone footage, macOS screen recordings, audio clips. Each item is stated as constraint -> implication -> mitigation.

---

## 1. iPhone footage

**Container/codec.** Default "High Efficiency" capture is HEVC in `.MOV`; "Most Compatible" is H.264. Pro models add ProRes (up to 4K120 only with external SSD recording), Apple Log (iPhone 15/16 Pro) and Apple Log 2 + ProRes RAW + genlock on iPhone 17 Pro ([iPhone 16 Pro specs](https://support.apple.com/en-us/121031), [iPhone 17 Pro specs](https://support.apple.com/en-us/125090), [CineD on ProRes RAW/genlock](https://www.cined.com/apple-iphone-17-pro-introduces-prores-raw-and-genlock-for-filmmakers/)). ProRes RAW requires Final Cut Camera 2.0 or Blackmagic Camera; genlock needs Blackmagic's ProDock ([CineD](https://www.cined.com/apple-final-cut-camera-2-0-open-gate-apple-log-2-and-prores-raw-genlock-for-iphone-17-pro/)). ffmpeg 8.0 added a native ProRes RAW decoder and 9.0 parses its linearization curves ([FFmpeg 8.0 announce](https://ffmpeg.org/pipermail/ffmpeg-devel/2025-August/347886.html), [jbkempf on 9.0](https://jbkempf.com/blog/2026/ffmpeg-9.0/)).
*Implication:* the common case is 10-bit HEVC HDR; ProRes/RAW/Log are edge cases we should accept but not optimize for.
*Mitigation:* probe every file with `ffprobe -print_format json -show_format -show_streams` and branch on codec/pix_fmt/color tags.

**HDR: Dolby Vision Profile 8.4 over HLG.** iPhone HDR video is Dolby Vision Profile 8.4, i.e. an HLG (BT.2020, `arib-std-b67`) base layer plus DV RPU metadata; non-DV players just get HLG ([Jellyfin PR discussion](https://github.com/jellyfin/jellyfin/pull/7828), [Apple DV PDF](https://developer.apple.com/av-foundation/Incorporating-HDR-video-with-Dolby-Vision-into-your-apps.pdf)). Naively converting to `yuv420p` without tone mapping produces the classic grey "washed out" look because PQ/HLG BT.2020 values are reinterpreted as BT.709 ([dev.to tone-mapping guide](https://dev.to/masonwritescode/ffmpeg-hdr-to-sdr-tone-mapping-that-doesnt-look-washed-out-2026-24ie)). Re-encoding with ffmpeg drops the RPU; people re-inject with `dovi_tool` if they want DV back ([MacRumors thread](https://forums.macrumors.com/threads/hdr-video-on-iphone-12-pro.2262787/page-10), [dovi_tool](https://github.com/quietvoid/dovi_tool)). Chrome on macOS displays HLG/PQ HDR correctly via EDR and handles DV Profile 8 as cross-compatible HLG ([StaZhu README](https://github.com/StaZhu/enable-chromium-hevc-hardware-decoding/blob/main/README.md)).
*Implication:* our proxies and SDR exports must tone-map, not just convert. Preserving DV on export is not realistic with ffmpeg alone.
*Mitigation:* SDR path: `libplacebo=apply_dolbyvision=true:tonemapping=bt.2390:colorspace=bt709:color_primaries=bt709:color_trc=bt709:format=yuv420p` (needs libplacebo -> `ffmpeg-full`), or CPU fallback `zscale=transfer=linear:npl=100,format=gbrpf32le,zscale=primaries=bt709,tonemap=hable,zscale=transfer=bt709:matrix=bt709:range=tv` ([dev.to](https://dev.to/masonwritescode/ffmpeg-hdr-to-sdr-tone-mapping-that-doesnt-look-washed-out-2026-24ie)). HDR-preserving path: keep HLG BT.2020 10-bit HEVC via `hevc_videotoolbox -profile:v main10 -pix_fmt p010le` and accept loss of DV RPU, or hand the export to AVFoundation (section 4). Verify tags with ffprobe after every render.

**Apple Log.** Log clips are ProRes 422 HQ with a flat log curve; Apple ships an `AppleLogToRec709` .cube LUT, applied in ffmpeg via `lut3d` ([jnjosh LUT automation](https://jnjosh.com/posts/automate-luts/), [Apple Community](https://discussions.apple.com/thread/255147293)). *Mitigation:* detect ProRes + iPhone model, apply the Apple LUT in proxy generation, let the user override.

**Variable frame rate.** All iOS camera apps record VFR; "target 30" can range 24-30 fps in low light with Auto FPS on ([ProVideo Coalition](https://www.provideocoalition.com/understanding-iphone-framerates-for-shooting-editing-distribution/), [Apple Community](https://discussions.apple.com/thread/256077798)). *Mitigation:* proxies and renders use `-fps_mode cfr -r <rate>` (the `-vsync` alias is deprecated and slated for removal in 9.x) ([ffmpeg-cookbook](https://ffmpeg-cookbook.com/en/articles/variable-framerate-to-constant/), [jbkempf 9.0 deprecations](https://jbkempf.com/blog/2026/ffmpeg-9.0/)).

**Rotation.** Portrait video is stored landscape with a display matrix ("displaymatrix: rotation of -90.00 degrees"); ffmpeg autorotates on encode by default and resets the flag; `-noautorotate` preserves the raw orientation ([Shotstack](https://shotstack.io/learn/rotate-videos-using-ffmpeg/), [ffmpeg trac #4612](https://trac.ffmpeg.org/ticket/4612)). *Mitigation:* keep autorotate on for proxies/renders; read `side_data_list[].rotation` from ffprobe to compute display dimensions in the UI.

**Spatial audio (iPhone 16/17).** With Spatial Audio on, the MOV carries a stereo AAC fallback plus an APAC first-order-ambisonic track and metadata tracks; tools that don't know APAC show them as "empty" tracks ([Apple Community](https://discussions.apple.com/thread/255785732), [WWDC25 session 251](https://developer.apple.com/videos/play/wwdc2025/251/)). ffmpeg has no APAC decoder; transcoding tools choke on it ([PhotoPrism discussion](https://github.com/photoprism/photoprism/discussions/5245), [Apple forums on AVAssetWriter failing](https://developer.apple.com/forums/thread/775865)). *Mitigation:* always `-map 0:v:0 -map 0:a:0` (first AAC stereo track) explicitly; never `-map 0`.

**Cinematic mode.** Depth is a second low-res grayscale HEVC stream (about 320x180 for 1080p) plus focus metadata; it is only present in "Export Unmodified Original" files and extraction needs a remux via MP4Box before ffmpeg can map it ([howiem.org](https://howiem.org/wordpress/2023/11/13/splitting-apple-cinematic-videos-into-image-and-depth-vids/), [Slashcam](https://www.slashcam.com/news/single/Technical-details-of-the-iPhone-13-Cinematic-Mode-16796.html)). *Mitigation:* treat Cinematic clips as flat video (the baked-in rack focus is fine); ignore the depth stream.

**Live Photos / HEIC.** A Live Photo is a HEIC plus a MOV linked by `ContentIdentifier` (`com.apple.quicktime.content.identifier` in the MOV, MakerApple in the HEIC), not by filename ([Apple Community](https://discussions.apple.com/thread/255584737), [theheictojpg](https://theheictojpg.com/heic/live-photos)). HEIC decoding: `heif-convert` from libheif (`brew install libheif`) is the reference path; ffmpeg's HEIC support depends on build flags; `sips` works but strips most EXIF ([convertio guide](https://convertio.com/heic-to-jpg/command-line), [libheif](https://github.com/strukturag/libheif)). *Mitigation:* pair by ContentIdentifier via exiftool/ffprobe tags; convert stills with `sips` or libheif before ingest.

**Metadata the AI can use.** ffprobe exposes `com.apple.quicktime.creationdate`, `com.apple.quicktime.location.ISO6709` (e.g. `+41.1971+019.1686+089.373/`), `com.apple.quicktime.make/model` in `format.tags` ([addpipe geolocation](https://blog.addpipe.com/geolocation-metadata-ios-android-video-files/), [gist on creationdate](https://gist.github.com/PatriceVignola/d612fc50fc25c2f2fd747b760eb4ad6f)). *Mitigation:* index these into the project database at ingest for "the clip I shot in Tirana on Tuesday" queries.

## 2. macOS screen recordings

Cmd-Shift-5 / QuickTime produce `.mov`; on Tahoe you can pick "SDR (Most Compatible)" = H.264 or "HDR" = HEVC, and Tahoe adds per-window recording; microphone is optional, but system audio still cannot be captured by the built-in tool ([Apple Support 102618](https://support.apple.com/en-us/102618), [smoothcapture guide](https://www.smoothcapture.app/blog/how-to-record-screen-on-mac)). Recordings are VFR ([ffmpeg-cookbook screen recording](https://ffmpeg-cookbook.com/en/articles/screen-recording/)). Retina captures are at 2x native size (3024x1964, 3456x2234), which are not multiples of 2 after typical scaling and trigger libx264's "height not divisible by 2" ([ffmpeg-cookbook](https://ffmpeg-cookbook.com/en/articles/fix-height-not-divisible-by-2/), [kerma notes](https://kerma.github.io/posts/downscale-screen-recording/)).
*Implication:* screen recordings will drift out of sync with audio if treated as CFR; no system audio means narration must be a separate mic track or captured by us.
*Mitigation:* `-fps_mode cfr -r 30` (or 60) plus `scale=-2:1080` / `scale=trunc(iw/2)*2:trunc(ih/2)*2`. If we ever record from the app, ScreenCaptureKit (macOS 12.3+) captures screen and system audio under the standard Screen Recording TCC grant, no driver required ([sck-record CLI](https://github.com/connerkward/macos-screen-recorder-system-audio), [creavit guide](https://creavit.studio/blog/screencapturekit-audio-recording-mac-guide)); note Sequoia's monthly re-approval prompt for third-party recorders ([9to5Mac](https://9to5mac.com/2024/08/14/macos-sequoia-screen-recording-prompt-monthly/)).

## 3. ffmpeg on macOS

**Versions.** FFmpeg 8.0 "Huffman" (Aug 2025) added the native Whisper filter, APV, ProRes RAW decoder, VVC improvements ([Phoronix](https://www.phoronix.com/news/FFmpeg-8.0-Released), [announce](https://ffmpeg.org/pipermail/ffmpeg-devel/2025-August/347886.html)). FFmpeg 9.0 "Lei" (2026) rewrote swscale, added animated WebP decode, Dolby Vision Profile 7 splitting, SMPTE 2094-50 metadata, and deprecated `-vsync` ([jbkempf](https://jbkempf.com/blog/2026/ffmpeg-9.0/), [9to5Linux](https://9to5linux.com/ffmpeg-9-0-lei-open-source-multimedia-framework-officially-released)). Homebrew's `ffmpeg` bottle is already 9.0.1 ([formulae.brew.sh](https://formulae.brew.sh/formula/ffmpeg)).

**What Homebrew enables.** Core `ffmpeg` (GPL-3.0-or-later; `--enable-gpl --enable-version3`) includes x264, x265, svt-av1, dav1d, libvpx, libvmaf, opus, lame, openssl, videotoolbox, audiotoolbox -- but NOT libass, libplacebo, zimg or whisper ([formula source](https://raw.githubusercontent.com/Homebrew/homebrew-core/HEAD/Formula/f/ffmpeg.rb)). `ffmpeg-full` (also homebrew-core, keg-only, bottled for Tahoe/Sequoia/Sonoma arm64) adds whisper-cpp, libplacebo, libass, zimg, libvmaf and much more ([formulae.brew.sh/ffmpeg-full](https://formulae.brew.sh/formula/ffmpeg-full)).
*Implication:* subtitle burn-in (`subtitles`/`ass` filters), libplacebo tone mapping and the Whisper filter all require `ffmpeg-full`; plain `brew install ffmpeg` will silently lack them.
*Mitigation:* depend on `ffmpeg-full` (or a pinned static build) and probe `ffmpeg -filters` at startup.

**Static builds and licensing.** Options: [Martin Riedl](https://ffmpeg.martin-riedl.de/) (arm64 macOS, stable URLs), [evermeet.cx](https://evermeet.cx/ffmpeg/) (Intel-only), [BtbN](https://github.com/BtbN/FFmpeg-Builds) (GPL/LGPL variants, Linux/Windows focus), and npm wrappers [ffmpeg-static](https://github.com/eugeneware/ffmpeg-static) / [ffmpeg-ffprobe-static](https://github.com/descriptinc/ffmpeg-ffprobe-static). Any build with x264/x265 is GPL; if we ever ship a closed binary alongside, use an LGPL build (VideoToolbox encoders and AudioToolbox AAC are LGPL-compatible) ([BtbN license variants](https://github.com/BtbN/FFmpeg-Builds)).

**VideoToolbox.** `h264_videotoolbox`, `hevc_videotoolbox` (Main and Main10 via `-profile:v main10 -pix_fmt p010le`) and `prores_videotoolbox` are available; hardware decode via `-hwaccel videotoolbox`; Apple Silicon decodes 8-10-bit HEVC 4:2:0/4:2:2/4:4:4 in hardware and AV1 from M3 ([codecs.wiki](https://codecs.wiki/docs/encoders_hw/videotoolbox), [Marc Griffith](https://medium.com/@marc.griffith/ffmpeg-command-line-video-encoding-with-hardware-acceleration-on-apple-silicon-72c5248cd398), [MacRumors Main10 thread](https://forums.macrumors.com/threads/hevc-main10-hardware-encoding.2219528/)). Quality control: `-q:v 0-100` exists but is device/OS-dependent; `-b:v` with `-maxrate/-bufsize` is the predictable knob ([ffmpeg-cookbook VideoToolbox](https://ffmpeg-cookbook.com/en/articles/hardware-encode-videotoolbox/)). Benchmarks on M1 Pro, 4K: default `hevc_videotoolbox` 1.72x realtime and "hazy"; `-q:v 50` 1.73x, sharp, but 171 MB vs 22 MB; `libx265 -crf 28 -preset fast` 0.116x (about 15x slower) at 24 MB ([yre.jp](https://yre.jp/en/post/m1mac_h265/)). Community consensus is q 45-55 for 4K ([b.27p.de](https://b.27p.de/p/00016-ffmpeg-apple-silicon-h265-encoding/)).
*Implication:* hardware encode is the only viable path for interactive proxy generation and previews; software x265 is a "final master, overnight" option.
*Mitigation:* proxies with `h264_videotoolbox -b:v`; masters with `hevc_videotoolbox -q:v 55` (or `-b:v` targets), with an optional libx265 "archival" preset.

**ffprobe JSON** (`-print_format json -show_format -show_streams -show_frames` etc.) is the inspection API; see [ffmpeg-api ffprobe guide](https://ffmpeg-api.com/docs/ffprobe) and VFR detection via frame timestamps ([dev.to VFR detection](https://dev.to/masonwritescode/detect-variable-frame-rate-uploads-with-ffprobe-and-normalize-them-before-they-break-your-pipeline-55cf)).

## 4. Native Apple alternatives

- **AVFoundation** (`AVMutableComposition` + `AVAssetExportSession`) gives perfect HEVC/ProRes/DV handling and HDR passthrough; presets include `AVAssetExportPresetHEVCHighestQualityWithAlpha` ([Apple docs](https://developer.apple.com/documentation/avfoundation/avassetexportpresethevchighestqualitywithalpha)). Apple's `avconvert` CLI ships in macOS with presets like `PresetHEVC3840x2160`, `PresetAppleProRes422LPCM`, `PresetHEVCHighestQuality` ([avconvert man page](https://keith.github.io/xcode-man-pages/avconvert.1.html)). Compressor ($49.99) adds HDR color-space conversion, watch folders and command-line JSON/XML batch submission ([App Store](https://apps.apple.com/us/app/compressor/id424390742)).
  *Implication:* the cons are weak filter flexibility; the pros make it the best HDR-preserving export path. *Mitigation:* Swift helper binary that takes an EDL JSON and renders via AVFoundation for "HDR master" exports; ffmpeg for everything else.
- **Speech.** macOS 26 `SpeechAnalyzer`/`SpeechTranscriber` transcribed a 34-minute 4K file in 45 s vs 1:41 for MacWhisper large-v3-turbo, similar quality ([MacStories](https://www.macstories.net/stories/hands-on-how-apples-new-speech-apis-outpace-whisper-for-lightning-fast-transcription/), [WWDC25 277](https://developer.apple.com/videos/play/wwdc2025/277/)). The `yap` CLI (`brew install yap`, macOS 26+) outputs txt/SRT/VTT/JSON with word timestamps ([yap](https://github.com/finnvoor/yap)). Argmax positions WhisperKit as complementary ([Argmax](https://www.argmaxinc.com/blog/apple-and-argmax)).
- **Foundation Models** (macOS 26): on-device ~3B LLM, Swift API with guided generation and tool calling, but a hard 4096-token context per session ([Apple docs](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window?changes=_3), [zats.io](https://zats.io/blog/making-the-most-of-apple-foundation-models-context-window/), [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/)). Useful for cheap per-clip labeling, not for planning an edit over a long transcript.
- **Vision** (face/text/body detection) and **Core ML / MLX** for custom models ([MLX](https://github.com/ml-explore/mlx)); **Core Image/Metal** for effects.
- **Calling from Node/Python:** ship small Swift CLI helpers (JSON in/out over stdio) built with `swift build`; PyObjC exists but ties us to Python and struggles with Swift-only frameworks like SpeechAnalyzer and Foundation Models. XPC is unnecessary for a single-user local tool.

## 5. Browser constraints on macOS

- **HEVC playback.** Chrome enabled HEVC hardware decode by default in 107 (Oct 2022, macOS 11+); WebCodecs HEVC decode from 107 (8-bit) / 108 (10-bit, alpha), encode from 130; HLG/PQ/HDR10 display and DV Profile 8 cross-compat are supported on macOS ([StaZhu README](https://github.com/StaZhu/enable-chromium-hevc-hardware-decoding/blob/main/README.md)). Electron 22+ inherits HEVC HW decode, 33+ HW encode (same source).
- **Safari/WKWebView.** WebCodecs `VideoDecoder` since Safari 16.4 (video-only); `AudioDecoder/AudioEncoder` only arrived in Safari 26 ([WebKit Safari 26 features](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/), [STP 157](https://webkit.org/blog/13575/release-notes-for-safari-technology-preview-157/)). Safari has no `showDirectoryPicker`/`showOpenFilePicker` -- only OPFS ([Cloud Four](https://cloudfour.com/thinks/the-many-confusing-file-system-apis/), [caniuse issue](https://github.com/Fyrd/caniuse/issues/6182)). Tauri on macOS uses WKWebView ([Tauri webview versions](https://v2.tauri.app/reference/webview-versions/)), so a Tauri shell inherits Safari's gaps.
- **Memory.** V8 caps a single ArrayBuffer at ~2 GB and a tab at roughly 4 GB; wasm32 is 4 GB ([Chromium issue 40055619](https://issues.chromium.org/issues/40055619), [Rust forum](https://users.rust-lang.org/t/chrome-wasm32-4gb-2gb-limits-workarounds/78161)). Never load whole clips into memory; stream from the local server with range requests.
- **Security context / autoplay.** `http://localhost` and `127.0.0.1` are potentially trustworthy, so secure-context-only APIs work without TLS ([MDN](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts)). Muted autoplay is always allowed; unmuted needs a user gesture or MEI ([Chrome autoplay policy](https://developer.chrome.com/blog/autoplay)).
*Implication:* Chromium is the only engine giving us HEVC + 10-bit WebCodecs + directory pickers + HDR display today. *Mitigation:* target Chrome (or Electron 33+) and gate features on `VideoDecoder.isConfigSupported`; avoid Tauri unless we accept ffmpeg-transcoded H.264 previews only.

## 6. Distribution and permissions

- **Gatekeeper/notarization.** Sequoia removed the Control-click bypass for unsigned/un-notarized software ([Apple Developer News](https://developer.apple.com/news/?id=saqachfa)); notarization requires the $99/year Developer Program ([Revenera](https://www.revenera.com/blog/software-installation/apples-application-notarization-for-macos/), [Apple memberships](https://developer.apple.com/support/compare-memberships/)). Anything we distribute (helper daemon, bundled ffmpeg, Electron app) must be Developer-ID signed with hardened runtime and notarized; brew-installed ffmpeg sidesteps this for dev builds.
- **Background process.** A per-user LaunchAgent (or `SMAppService`, macOS 13+, which surfaces in System Settings > Login Items) is sufficient; no root daemon needed ([Apple SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)).
- **TCC.** Reading `~/Pictures/Photos Library.photoslibrary` from a terminal process trips TCC per-container prompts; Full Disk Access on the host terminal/app is the practical fix ([HackTricks TCC](https://hacktricks.wiki/en/macos-hardening/macos-security-and-privilege-escalation/macos-security-protections/macos-tcc/index.html), [hermes-webui issue](https://github.com/nesquena/hermes-webui/issues/1485)). `osxphotos` reads the Photos database, exports originals/edited/Live Photo movies, and can ask Photos to download iCloud-offloaded originals via AppleScript or experimental PhotoKit; Tahoe support is "limited testing" ([osxphotos README](https://github.com/RhetTbull/osxphotos/blob/main/README.md)). Sandboxed Electron apps cannot reach the Photos library at all ([Apple forums](https://developer.apple.com/forums/thread/762839)). Screen Recording and Microphone permissions are needed only if we capture ourselves; Sequoia re-prompts monthly ([9to5Mac](https://9to5mac.com/2024/08/14/macos-sequoia-screen-recording-prompt-monthly/)).
- **Unified memory / thermals.** CPU, GPU and ANE share one pool; whisper large-v3-turbo peaks around 6 GB RAM ([JustVoice benchmark](https://justvoice.ai/blog/whisper-benchmark-apple-silicon-m3-m4)); fanless MacBook Airs throttle after 10-15 minutes of sustained inference ([SitePoint](https://www.sitepoint.com/local-llm-hardware-requirements-mac-vs-pc-2026/), [promptquorum](https://www.promptquorum.com/local-llms/apple-silicon-local-llm-guide-2026)).
*Mitigation:* run transcription, LLM and encode as a serialized job queue with a memory budget (e.g. never co-schedule Whisper and a >7B LLM on 16 GB machines); prefer SpeechAnalyzer, which offloads to Apple's shared system model and avoids a 6 GB Whisper footprint.

## Platform decisions

1. **ffmpeg source:** Homebrew `ffmpeg-full` 9.x for development (libplacebo, libass, whisper, zimg present); for distribution, a pinned static arm64 build (Martin Riedl or self-built) and honor GPL, or an LGPL build if we ever ship closed code alongside.
2. **Encoder defaults:** `h264_videotoolbox` for proxies (`-b:v 6M -maxrate 8M`, 1080p, `-fps_mode cfr`); `hevc_videotoolbox -q:v 55` for SDR masters; `hevc_videotoolbox -profile:v main10 -pix_fmt p010le` or an AVFoundation Swift helper for HDR masters; `libx265` only as an opt-in "archival" preset.
3. **Proxy strategy:** always generate CFR, even-dimension, autorotated, SDR BT.709 H.264 proxies at ingest (tone-mapped via libplacebo for HLG/DV sources, Apple LUT for Log); keep originals untouched; expect ~2-3 GB/hour of proxy storage.
4. **Audio mapping:** explicitly map the first stereo AAC track; never `-map 0`; drop APAC and metadata tracks.
5. **Browser target:** Chrome (or Electron 33+) only; require WebCodecs 10-bit HEVC and File System Access; no Tauri/WKWebView.
6. **Photos access:** `osxphotos export --download-missing` driven from the helper, with Full Disk Access requested once for the helper process; fall back to drag-and-drop of exported originals.
7. **Transcription:** SpeechAnalyzer via a Swift helper (or `yap`) on macOS 26 as default; whisper.cpp/WhisperKit large-v3-turbo as fallback on macOS 15 or for non-supported languages.
8. **Color-management policy:** store source color tags from ffprobe; edit and preview in SDR BT.709 proxies; export SDR by default with proper tone mapping; offer HDR (HLG BT.2020) export only when all sources are HDR; never claim Dolby Vision on output.
9. **Metadata indexing:** ingest `creationdate`, `location.ISO6709`, `make/model`, rotation, VFR stats, HDR flags into the project DB for the AI planner.
10. **Process model:** signed, notarized user LaunchAgent (SMAppService) hosting a localhost HTTP server; serialized job queue with a memory budget; ffmpeg runs as a child process with progress parsed from `-progress pipe:1`.
