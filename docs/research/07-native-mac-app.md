# Native macOS AI Video Editor: Feasibility & Comparison (researched 2026-09-08)

Method note: web search quota was exhausted in this session, so every claim below was verified by fetching primary sources directly (Apple doc JSON endpoints, WWDC transcripts, GitHub READMEs, Anthropic/MCP docs). Apple's docs now reference macOS 27 (WWDC26, June 2026), so "current" below means macOS 26 shipping + 27 beta.

## 1. Apple's media stack for editing

**Composition model.** `AVMutableComposition` lets you "add and remove composition tracks, and add, remove, and scale their time ranges"; an immutable copy is directly playable via `AVPlayerItem(asset:)` and exportable, no intermediate rendering (https://developer.apple.com/documentation/avfoundation/avmutablecomposition). This is the killer feature you asked about: **yes, AVPlayer plays a multi-track composition with a video composition and audio mix applied live**. `AVPlayerItem.videoComposition` is "the video composition settings to be applied during playback" (file-based media only, not HLS) (https://developer.apple.com/documentation/avfoundation/avplayeritem/videocomposition). Custom compositors (`AVVideoCompositing`) are explicitly used by "`AVPlayerItem`, `AVAssetExportSession`, `AVAssetImageGenerator`, and `AVAssetReaderVideoCompositionOutput`" (https://developer.apple.com/documentation/avfoundation/avvideocompositing), so one Metal/Core Image compositor serves preview, thumbnails and export. Per-frame Core Image without writing a compositor: `AVMutableVideoComposition(asset:applyingCIFiltersWithHandler:)` works "whether for display or export" (the completion-handler variant replaces the deprecated one) (https://developer.apple.com/documentation/avfoundation/avmutablevideocomposition/init(asset:applyingcifilterswithhandler:)).

**Scrub accuracy.** By default "item timing is updated as quickly as possible during seeking" and does not wait for composited frames; set `seekingWaitsForVideoCompositionRendering = true` so timing updates "only after the corresponding video frame has been displayed", which also keeps an `AVSynchronizedLayer` in sync (https://developer.apple.com/documentation/avfoundation/avplayeritem/seekingwaitsforvideocompositionrendering). Expect heavier compositors to make scrubbing feel laggy; use `seek(to:toleranceBefore:toleranceAfter:)` with zero tolerance and proxy media for 4K HEVC.

**Core Animation overlays: the export-only trap is real.** `AVVideoComposition.animationTool` is "a video composition tool to use with Core Animation in offline rendering... Set an animation tool if you're using the composition in conjunction with `AVAssetExportSession` for offline rendering, rather than with `AVPlayer`" (https://developer.apple.com/documentation/avfoundation/avvideocomposition/animationtool). For preview you overlay an `AVSynchronizedLayer`, which "confers its timing state, synchronizing the timing of layers in its subtree with that of a player item" (https://developer.apple.com/documentation/avfoundation/avsynchronizedlayer). Both require `beginTime = AVCoreAnimationBeginTimeAtZero` (Core Animation replaces 0 with `CACurrentMediaTime()`), `isRemovedOnCompletion = false`, and no view-backed layers; animations are "interpreted on the video's timeline, not real-time" (https://developer.apple.com/documentation/avfoundation/avvideocompositioncoreanimationtool). Consequence: captions built on CALayer live in two code paths (sync layer for preview, animation tool for export) that can drift. Rendering captions inside your custom compositor (Core Image/Metal) avoids the duality; see section 5.

**Transitions** require either built-in `AVVideoCompositionLayerInstruction` opacity/transform ramps or a custom compositor; Apple's reference is the 2017 AVCustomEdit sample (ObjC + Swift/Metal, cross-dissolve/wipe) (https://developer.apple.com/library/archive/samplecode/AVCustomEdit/Introduction/Intro.html) and the 2013 AVCompositionDebugViewer for visualizing tracks, instructions and audio ramps (https://developer.apple.com/library/archive/samplecode/AVCompositionDebugViewer/Introduction/Intro.html). Both are old but still the canonical shapes.

**Export.** `AVAssetExportSession` now has async `export(to:as:isolation:)` and a `states(updateInterval:)` async sequence; `exportAsynchronously`, `progress` and `status` are deprecated (https://developer.apple.com/documentation/avfoundation/avassetexportsession). For full control, `AVAssetReader` + `AVAssetWriter` (writes .mov/.mp4, pixel-buffer receivers, "use... in conjunction with AVAssetReader for transcoding") (https://developer.apple.com/documentation/avfoundation/avassetwriter).

**HDR / Dolby Vision.** The built-in compositor handles HDR automatically ("chances are that you will get HDR video out with the same composition instructions"). A custom compositor must set `supportsHDRSourceFrames = true` (else "the framework... will convert them to standard dynamic range before sending it to you") and advertise 10-bit formats like `kCVPixelFormatType_420YpCbCr10BiPlanarVideoRange`; custom Metal CI kernels must be HDR-aware (values >1.0); color policy prefers HLG over PQ over SDR (https://developer.apple.com/videos/play/wwdc2020/10009/). Export: HEVC or ProRes presets preserve HDR with no changes; with AVAssetWriter set BT.2020 primaries/matrix, HLG or PQ transfer, and `HEVC_Main10_AutoLevel` ("8-bit HEVC HDR is not supported") (https://developer.apple.com/videos/play/wwdc2020/10010/). iPhone footage is Dolby Vision (HLG-based); per-frame DV metadata for your own writer pipeline comes from `VTHDRPerFrameMetadataGenerationSession` with `.dolbyVision` (macOS 15+) (https://developer.apple.com/documentation/videotoolbox/vthdrperframemetadatagenerationsession/hdrformat). Display: EDR via `CAMetalLayer.wantsExtendedDynamicRangeContent`, RGBA16Float, and `AVPlayerItemVideoOutput` doing color conversion for you (https://developer.apple.com/videos/play/wwdc2022/110565/). Apple's sample "Editing and playing HDR video" (macOS 11+) is the starting point (https://developer.apple.com/documentation/avfoundation/editing-and-playing-hdr-video).

**Hardware.** VideoToolbox exposes hardware encode/decode sessions (https://developer.apple.com/documentation/videotoolbox); M5-family Macs list "Hardware-accelerated H.264, HEVC, ProRes, and ProRes RAW... ProRes encode and decode engine... AV1 decode" (https://www.apple.com/macbook-pro/specs/). Bonus for an AI editor: `VTFrameProcessor` (macOS 15.4+) gives ML frame-rate conversion (slow-mo), super resolution, motion blur and temporal denoise (https://developer.apple.com/videos/play/wwdc2025/300/).

**Audio limits.** `AVMutableAudioMixInputParameters` gives volume ramps, time-pitch algorithm and an `audioTapProcessor` (https://developer.apple.com/documentation/avfoundation/avmutableaudiomixinputparameters); `MTAudioProcessingTap` is the only hook for "real-time audio processing of AVPlayer and audio mix tracks" (https://developer.apple.com/documentation/mediatoolbox), a C callback API with no Audio Unit graph. Per-clip EQ/compression means running `AVAudioEngine` in manual rendering mode offline (macOS 10.13+) and writing processed audio back into the composition (https://developer.apple.com/documentation/avfaudio/avaudioengine/enablemanualrenderingmode(_:format:maximumframecount:)).

**Free analysis/AI frameworks.** Vision: faces/landmarks, body/hand pose, `RecognizeTextRequest`/`RecognizeDocumentsRequest`, attention/objectness saliency, person and foreground instance masks, object tracking, optical flow, aesthetics scoring (https://developer.apple.com/documentation/vision). Speech: `SpeechAnalyzer`/`SpeechTranscriber` (macOS 26+), on-device, long-form, with `audioTimeRange` per attributed-string run (https://developer.apple.com/documentation/speech/speechtranscriber, https://developer.apple.com/videos/play/wwdc2025/277/). SoundAnalysis classifies 300+ sounds (https://developer.apple.com/documentation/soundanalysis). Foundation Models: macOS 26 on-device 3B model, `@Generable` constrained decoding, `Tool` protocol, 4,096-token context (https://developer.apple.com/documentation/foundationmodels/managing-the-context-window, https://developer.apple.com/videos/play/wwdc2025/286/); macOS 27 rebuilds the model (8,192 tokens, vision, better tool calling), adds `PrivateCloudComputeLanguageModel` (32K context, reasoning, managed entitlement), `DynamicProfile` for agentic orchestration, an `fm` CLI, and open-sources the framework (https://developer.apple.com/videos/play/wwdc2026/241/, https://developer.apple.com/documentation/foundationmodels/privatecloudcomputelanguagemodel, https://developer.apple.com/videos/play/wwdc2026/242/). Core ML runs across CPU/GPU/ANE (https://developer.apple.com/documentation/coreml); MLX Swift (MIT) for local LLM/Whisper-class models (https://github.com/ml-explore/mlx-swift). Image Playground (macOS 15.1+) gives a system sheet plus a programmatic `ImageCreator` (docs now mark it deprecated, so check the 27 SDK) (https://developer.apple.com/documentation/imageplayground); Genmoji appear in attributed text as `NSAdaptiveImageGlyph` (https://developer.apple.com/documentation/appkit/nsadaptiveimageglyph). PhotoKit gives `requestAVAsset`/`requestExportSession` for iPhone footage (https://developer.apple.com/documentation/photokit). ScreenCaptureKit (macOS 12.3+) delivers `CMSampleBuffer`s with audio; pair with AVAssetWriter (https://developer.apple.com/documentation/screencapturekit).

**Do you still want ffmpeg?** Probably, as an optional sidecar for exotic containers, GIF/WebM/AV1 encode, `ffprobe`, and filters AVFoundation lacks. Licensing: FFmpeg is LGPL 2.1+ unless built with `--enable-gpl` (x264/x265) which makes "the GPL apply to all of FFmpeg"; their checklist requires dynamic linking, shipping matching sources, and documenting the build (https://ffmpeg.org/legal.html). Popular prebuilt macOS binaries are GPL and Intel-only ("I do not plan to provide native ffmpeg binaries for Apple Silicon") (https://evermeet.cx/ffmpeg/); ffmpeg-kit was archived July 2, 2026 in favor of FFmpegKitNext (https://github.com/arthenica/ffmpeg-kit). Plan to build an LGPL arm64 ffmpeg yourself. Notarization requires Developer ID signing of every nested executable, hardened runtime and a secure timestamp; verify with `codesign -vvv --deep --strict` (https://developer.apple.com/documentation/security/resolving-common-notarization-issues). App Sandbox is mandatory only for the Mac App Store (https://developer.apple.com/documentation/security/app-sandbox).

## 2. SwiftUI vs AppKit for the timeline

SwiftUI `Canvas` is immediate-mode and fast for "complex drawing that involves dynamic data", but "doesn't offer interactivity or accessibility for individual elements" (https://developer.apple.com/documentation/swiftui/canvas). Practical pattern: SwiftUI for chrome (inspector, library, toolbars), and an `NSViewRepresentable` timeline whose ruler/clips/waveforms are drawn in a `CAMetalLayer` or tiled `CALayer`s, with AppKit gesture/scroll-wheel handling; clip hit-testing stays in your model. Apple's performance guidance: keep view bodies fast and dependencies granular, profile with the SwiftUI instrument in Instruments 26 (https://developer.apple.com/videos/play/wwdc2025/306/). WWDC26 adds a `ContentBuilder` that gives "a substantial improvement in type checking performance", reorderable containers, and a new snapshot-based `Document` protocol for editors (https://developer.apple.com/videos/play/wwdc2026/269/).

Reusable pieces: DSWaveformImage (macOS 12+, SwiftUI `WaveformView`/`WaveformLiveCanvas`/`WaveformShape`) (https://github.com/dmrschmidt/DSWaveformImage); AudioKitUI (macOS 10.15+, MIT) (https://github.com/AudioKit/AudioKitUI); FDWaveformView is iOS-only (https://github.com/fulldecent/FDWaveformView). Composition frameworks to study rather than depend on: Cabbage (iOS 9+, Swift 4, timeline -> `AVPlayerItem`/export) (https://github.com/VideoFlint/Cabbage) and VideoLab (iOS 11+, AVFoundation + Metal custom compositor, multi-layer, transitions, CALayer text animation) (https://github.com/ruanjx/VideoLab). I found no maintained open-source Swift macOS NLE; expect to own the timeline component.

## 3. Calling Claude from Swift

There is **no official Anthropic Messages client for Swift**; official SDKs are Python, TypeScript, C#, Go, Java, PHP, Ruby (https://platform.claude.com/docs/en/cli-sdks-libraries/overview). But Anthropic now ships **ClaudeForFoundationModels** (Apache-2.0, beta): a Swift package conforming Claude to Apple's `LanguageModel` protocol so `LanguageModelSession` drives Claude with streaming, `@Generable` structured output, client-side `Tool`s, server tools (web search/fetch, code execution), image input and App Attest auth; it requires macOS 27/Xcode 27 and omits caching controls, batches, Files API, token counting and beta headers (https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/apple-foundation-models, https://github.com/anthropics/ClaudeForFoundationModels). Apple's session confirms "Anthropic and Google will soon extend the Foundation Models framework with Swift packages" and that `LanguageModel` supports tool calling and guided generation capabilities (https://developer.apple.com/videos/play/wwdc2026/339/). For macOS 26 today, community SDKs cover the Messages API: SwiftAnthropic (MIT, macOS 12+, streaming, tools, thinking, caching, batches) (https://github.com/jamesrochabrun/SwiftAnthropic), AnthropicSwiftSDK (https://github.com/fumito-ito/AnthropicSwiftSDK), or hand-rolled URLSession.

The Claude Agent SDK "is available as a library for Python and TypeScript only. To drive the same agent loop from another language, run the CLI as a subprocess with the `-p` flag and `--output-format json`" (https://code.claude.com/docs/en/agent-sdk/overview); `stream-json` with `--include-partial-messages`, `--mcp-config`, `--allowedTools`, `--resume`, and `--bare` make a supervised Node sidecar viable (https://code.claude.com/docs/en/headless).

MCP: `modelcontextprotocol/swift-sdk` implements Client and Server with `StdioTransport`, `HTTPClientTransport`, `StatelessHTTPServerTransport`, `StatefulHTTPServerTransport` (SSE) and `NetworkTransport`; Swift 6.0+/macOS 13+, pre-1.0 (https://github.com/modelcontextprotocol/swift-sdk, https://github.com/modelcontextprotocol/swift-sdk/releases). Claude Code attaches with `claude mcp add --transport http <name> http://127.0.0.1:<port>/mcp` (https://code.claude.com/docs/en/mcp); the spec requires local servers to validate `Origin` and bind to 127.0.0.1 (https://modelcontextprotocol.io/specification/2025-06-18/basic/transports). Offline agent: Foundation Models `Tool` calling with `DynamicProfile`, `.toolCallingMode(.required)` and `historyTransform` for context trimming (https://developer.apple.com/videos/play/wwdc2026/242/).

## 4. Comparison for this project

| Dimension | Native (SwiftUI/AppKit + AVFoundation) | (a) Web UI + local ffmpeg daemon | (b) Electron/Tauri | (c) Native shell + WKWebView timeline + Swift core |
|---|---|---|---|---|
| Real-time multitrack preview | Best: AVPlayer plays compositions with custom compositor live; scrub via `seekingWaitsForVideoCompositionRendering` | Worst: browser can't play an AVComposition; you pre-render proxies or stream from ffmpeg | Tauri is WKWebView (https://v2.tauri.app/reference/webview-versions/), same limits as (a); Electron adds Chromium | Preview stays native (AVPlayerLayer under/near the web view); timeline drawn in JS |
| HDR/HEVC/ProRes correctness | Native HDR pipeline, hardware ProRes/HEVC, Dolby Vision metadata | ffmpeg can pass through but browser preview is SDR/8-bit | same as (a) | Native for render/preview |
| Performance/battery | Best | Extra process + IPC + browser | Chromium overhead | Good; JS timeline is cheap |
| Dev velocity (TS-strong, Swift-moderate) | Slowest at first: AVFoundation gotchas, Metal, Swift 6 concurrency | Fastest UI; but media engine is the hard part and ffmpeg has no composition/preview model | Fast UI | Fast UI, native media; two languages and a bridge |
| Agent tooling/testability | Tools = pure Swift functions over `EditorCore`; Swift Testing; MCP server in-process | Tools = TS functions; easy to test; daemon is already an MCP server | Same as (a) | Tools in Swift core; web UI observes state |
| External drive (Claude Code) | Swift MCP HTTP server; App Intents/Shortcuts (Spotlight on Mac runs intents, https://developer.apple.com/videos/play/wwdc2025/275/) | MCP over HTTP trivially | same | same as native |
| LLM writing/testing UI | Xcode 27 agents build, run tests, render previews (https://developer.apple.com/videos/play/wwdc2026/259/); snapshot tests via swift-snapshot-testing (https://github.com/pointfreeco/swift-snapshot-testing) | Playwright/Vitest, very LLM-friendly | same | Mixed |
| Testing | Swift Testing (https://developer.apple.com/documentation/testing), XCUITest, ViewInspector (https://github.com/nalexn/ViewInspector), AppIntentsTesting (https://developer.apple.com/videos/play/wwdc2026/295/) | Web testing stack | same | Both |
| Distribution | Developer ID + notarization; MAS optional | Two artifacts (daemon + UI) | Large bundle | Single bundle |
| Maintenance | One toolchain, yearly OS churn | npm + ffmpeg builds | Electron/Tauri upgrades | Two toolchains |

Verdict: the media engine must be AVFoundation regardless of UI, because only it gives live composition preview with correct HDR on Apple Silicon. Once the engine is Swift, the marginal cost of a native UI is the timeline component. Option (c) is the pragmatic hedge if timeline UI velocity dominates: build `EditorCore`/`RenderKit` natively, host a TypeScript timeline in `WKWebView` with `callAsyncJavaScript`/`WKScriptMessageHandler` messaging (https://developer.apple.com/documentation/webkit/wkwebview), and keep the option to replace the web timeline with a Metal view later. Pure (a)/(b) should be rejected for this product.

## 5. Architecture sketch (native)

Swift Package workspace, App target thin:

- **EditorCore** (pure Swift, no AVFoundation): `Project { tracks: [Track]; clips: [Clip] }` with `CMTime`-like rational times, value types, `Sendable`. Operations are data: `enum EditOp { insert, trim, split, move, setTransition, addCaption, ... }` applied via `Project.apply(op) throws -> Project`, giving undo/redo and deterministic replay. Every AI tool maps 1:1 to an `EditOp` or query, so tools are testable with Swift Testing without media files.
- **RenderKit**: `Project -> (AVMutableComposition, AVMutableVideoComposition, AVMutableAudioMix)` compiler; one `AVVideoCompositing` Metal compositor handling transitions, PiP, memes/stickers, and captions; HDR-capable per section 1; `AVPlayerItem` factory for preview; async `AVAssetExportSession` and an `AVAssetReader/Writer` path for ProRes/DV. Snapshot-test frames via `AVAssetImageGenerator` and swift-snapshot-testing.
- **AnalysisKit**: actors wrapping Vision (faces, saliency for auto-reframe, text), SpeechTranscriber (word timings for captions and silence removal), SoundAnalysis, VTFrameProcessor; outputs typed `Annotation` timelines cached per asset.
- **AgentKit**: `Tool` conformances over EditorCore/AnalysisKit; two backends behind one protocol: `ClaudeForFoundationModels` (macOS 27) or a Messages-API client, and `SystemLanguageModel` for offline/small tasks; an in-process MCP Streamable-HTTP server (swift-sdk) exposing the same tools so Claude Code can drive the app; optional Claude Code sidecar via `claude -p --output-format stream-json`. App Intents mirror the top-level tools for Shortcuts/Spotlight.
- **App**: SwiftUI shell; timeline as `NSViewRepresentable` Metal view; preview `AVPlayerLayer` plus `AVSynchronizedLayer` only for lightweight UI overlays.

**Animated captions.** Recommended: render captions inside the custom compositor. Lay out `NSAttributedString` with Core Text into a Core Image/Metal texture per frame (or cache glyph atlases), animate via keyframes in `EditorCore`; one code path for preview and export, HDR-safe if you tag the overlay as SDR-in-HLG. `CATextLayer` supports attributed strings but "disables sub-pixel antialiasing" and forces the export-only animation tool plus a separate `AVSynchronizedLayer` path (https://developer.apple.com/documentation/quartzcore/catextlayer). libass (ISC; FreeType/HarfBuzz/fribidi) is a solid third option for karaoke-style ASS effects and importing existing subtitle styles, rendered to bitmaps and composited in the same compositor (https://github.com/libass/libass).

## Risks, honestly

1. AVFoundation learning curve: the animation tool export-only split, `beginTime` quirks, custom compositor HDR pixel formats, and the fact that Apple's editing samples date from 2013-2017. 2. Audio: no per-clip effects without a tap or an offline `AVAudioEngine` pass. 3. SwiftUI performance cliffs on long timelines; assume AppKit/Metal for the timeline from day one. 4. Foundation Models is small (4K/8K context) and the Claude bridge requires macOS 27 beta today; keep a Messages-API fallback. 5. App Intents are a good Shortcuts/Spotlight surface but Apple's 2025-26 sessions do not mention MCP; treat your own MCP server as the agent surface. 6. MCP swift-sdk is pre-1.0 with breaking minor releases. 7. Solo TS developer: budget for Swift 6 strict concurrency and Xcode iteration speed; Xcode 27's agents mitigate this but don't remove it.
