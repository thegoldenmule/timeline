## 2. Video understanding ("senses")

### 2a. Letting an LLM see footage
- **Frame sampling + Claude/GPT vision.** Claude accepts up to 100 images per API request (32 MB, 2000x2000 cap over 20 images); images cost ~(w*h)/750 tokens, so a 1568px-long-edge frame is ~1,600 tokens (~$0.005 on Sonnet 4.6 at $3/M). Sample one frame per shot (from scene detection) plus a contact-sheet grid to cut cost. [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision), [pricing](https://benchlm.ai/anthropic/api-pricing).
- **Gemini native video** is the only major API that ingests whole video with audio: 1 FPS default, ~100 tok/s at low res (~300 at high), 32 tok/s audio, up to 3 h per 1M-context request, Files API up to 20 GB, clipping via `start_offset/end_offset`, custom `fps`, timestamp (`MM:SS`) referencing. Gemini 2.5 Flash was $0.30/M input (so ~$0.02 per minute of video at low res). On 2026-09-01 Google launched **agentic video understanding** (Gemini 3.5 Flash-Lite through 3.8 Flash) that chooses which segments/modality to look at, reporting up to 88% fewer tokens and 66% lower cost at no feature fee. [Video understanding docs](https://ai.google.dev/gemini-api/docs/video-understanding), [Google announcement](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-agentic-video-in-gemini/), [Gemini pricing](https://www.cloudzero.com/blog/gemini-pricing/).
- **Open VLMs locally:** Qwen3-VL (256K native context, "second-level indexing" of video), InternVL3.5, VideoLLaMA3, Apple FastVLM (fast TTFT, runs on Mac). On Apple Silicon serve them via `vllm-mlx` (OpenAI/Anthropic-compatible, prefix caching for vision embeddings: 24.7x speedup on repeated video queries) or Ollama (Qwen3-VL 8B works; Gemma 3 vision spotty). Ollama switched its Mac backend to MLX in v0.19 (Mar 2026). Apple's on-device Foundation Model (AFM 3, macOS 27) accepts images directly. [Qwen3-VL guide](https://www.bentoml.com/blog/multimodal-ai-a-guide-to-open-source-vision-language-models), [vllm-mlx](https://github.com/waybarrios/vllm-mlx), [MLX inference paper](https://arxiv.org/html/2601.19139v2), [InternVL](https://github.com/opengvlab/internvl), [FastVLM](https://www.ultralytics.com/blog/fastvlm-apple-introduces-its-new-fast-vision-language-model), [Ollama vision notes](https://insiderllm.com/guides/vision-models-locally/).
- **Embeddings for semantic search:** SigLIP 2 (Apache-2.0) via `open_clip`/transformers, or `mlx_clip` on MLX. Caveat from Mixpeek's 2026 benchmark: averaging 8 SigLIP frame embeddings scores poorly (0.325 NDCG@10) for video-level retrieval; it is fine for *frame/shot*-level "find the frame with the dog" search, which is what an editor needs. [SigLIP 2](https://huggingface.co/blog/siglip2), [mlx_clip](https://github.com/harperreed/mlx_clip), [Mixpeek benchmark](https://mixpeek.com/blog/video-embedding-benchmark-2026).

### 2b. Deterministic analyzers
- **Shot boundaries:** PySceneDetect (`pip install scenedetect`, BSD-3; Content/Adaptive/Threshold/Hash/Histogram detectors; CSV/EDL output; Python API `detect(path, AdaptiveDetector())`). TransNetV2 (MIT, TF/PyTorch) catches dissolves/wipes. ffmpeg `scdet`/`select='gt(scene,0.4)'` as zero-dependency fallback. [PySceneDetect](https://github.com/breakthrough/pyscenedetect), [TransNetV2](https://github.com/soCzech/TransNetV2), [benchmark comparison](https://github.com/albanie/shot-detection-benchmarks).
- **Silence / dead air:** ffmpeg `silencedetect` (parse stderr), or **auto-editor** (Unlicense/public domain; audio-loudness or motion thresholds; exports Premiere/Resolve/FCP XML, ShotCut, Kdenlive, clip JSON). jumpcutter is the ancestor; carykh's original and `emkademy/jumpcutter` on PyPI. [ffmpeg filters](https://ffmpeg.org/ffmpeg-filters.html), [auto-editor](https://github.com/WyattBlue/auto-editor), [jumpcutter](https://github.com/carykh/jumpcutter).
- **Faces:** Apple Vision (`VNDetectFaceRectanglesRequest`, free, ANE; callable from Python via PyObjC or a Swift CLI), MediaPipe Face Detector/Landmarker (`pip install mediapipe`, Apache-2.0, 30+ FPS on CPU), insightface (code MIT but **models non-commercial**). For auto-reframe to 9:16 see `auto-vertical-reframe` (PySceneDetect + YOLO-seg + ByteTrack + MediaPipe) and Google AutoFlip. [Vision via PyObjC](https://yasoob.me/posts/how-to-use-vision-framework-via-pyobjc/), [MediaPipe face](https://developers.google.com/edge/mediapipe/solutions/vision/face_detector/python), [insightface license](https://github.com/deepinsight/insightface), [auto-vertical-reframe](https://github.com/KazKozDev/auto-vertical-reframe), [AutoFlip](https://opensource.googleblog.com/2020/02/autoflip-open-source-framework-for.html).
- **Objects:** Ultralytics YOLO26/11 is AGPL-3.0 (or paid enterprise license) - a problem for a closed product. Apache-2.0 alternatives: **RF-DETR** (Roboflow, DINOv2 backbone, >60 AP COCO), YOLOX, LibreYOLO (MIT). [Ultralytics license](https://www.ultralytics.com/license), [RF-DETR](https://github.com/roboflow/rf-detr), [alternatives](https://www.libreyolo.com/articles/best-ultralytics-alternatives).
- **OCR (screen recordings):** Apple Vision `RecognizeTextRequest` (macOS 15+ async Swift API) is the best on-device choice for UI text; wrap as CLI or use `ocrmypdf-appleocr`/PyObjC. PaddleOCR (PP-OCRv5, Apache-2.0) for multilingual; Tesseract (Apache-2.0) as lightweight fallback. [Vision text (2026)](https://danielsaidi.com/blog/2026/01/10/detecting-text-in-images-with-the-vision-framework), [ocrmypdf-appleocr](https://pypi.org/project/ocrmypdf-appleocr/), [OCR comparison 2026](https://unstract.com/blog/best-opensource-ocr-tools/).
- **Beats / music sync:** madmom `RNNBeatProcessor` + `DBNBeatTrackingProcessor` (BSD, best accuracy incl. downbeats), librosa `beat_track` (ISC, simplest), Essentia (AGPL - avoid), aubio (GPL). [madmom](https://dl.acm.org/doi/10.1145/2964284.2973795), [realtime madmom example](https://github.com/Sma1033/Realtime-beat-tracking).
- **Loudness:** ffmpeg `loudnorm` two-pass (measure JSON, then `linear=true` with measured values) to EBU R128 targets, e.g. I=-14 LUFS for social, TP=-1 dBTP. [loudnorm guide](https://dev.to/masonwritescode/two-pass-loudness-normalization-with-ffmpeg-loudnorm-the-right-way-1nm3), [filter ref](https://ayosec.github.io/ffmpeg-filters-docs/8.0/Filters/Audio/loudnorm.html).

## 5. Local LLMs on Apple Silicon

- **Ollama** (MIT daemon; MLX backend since v0.19; OpenAI/Anthropic-compatible API, tool calling, structured output, vision). Best for a background service.
- **LM Studio** (closed-source, free for personal *and* work use since July 2025; MLX backend was ~46% faster than Ollama's llama.cpp path on M4 Pro in Mar 2026; local server). Good for dev browsing, awkward to bundle.
- **MLX / mlx-lm / vllm-mlx / Rapid-MLX** - fastest native path when you control the runtime; vllm-mlx adds continuous batching and MCP tool calling.
- **llama.cpp** - lowest-level, GGUF, Metal.
- **Apple Foundation Models** - on-device 3B model (AFM 3 Core; 20B sparse "Core Advanced" announced at WWDC26), **4,096-token context on macOS 26 (8,192 on macOS 27)**, guided/structured generation and tool calling built in, image input in the rebuilt model; free and offline but requires Apple Intelligence enabled. Apple's official `fm` CLI + Python SDK ship with macOS 27; today use Swift or third-party CLIs (`rudrankriyam/Foundation-Models-Framework-CLI`, `apfel` with OpenAI-compatible server, `afm-cli` with `--schema` JSON). Realistic use: per-segment summaries, caption cleanup, keyword tagging, yes/no classification of clips - not whole-transcript reasoning (context too small).
- Realistic split: a 30B-class MLX model (Qwen3.x 30B-A3B / 27B 4-bit on a 32-64 GB Mac at ~100 tok/s) can summarize transcripts, rank candidate highlights and pick cut points acceptably; final creative direction, taste judgments and long multi-file planning should still go to Claude/Gemini.

## 6. Recommended "senses" pipeline (ingest -> per-media artifacts)

Run on import, all local, cached under `<project>/.analysis/<media-hash>/`:

1. `probe.json` - ffprobe streams, duration, fps, rotation (iPhone HEVC/HDR flags matter for later rendering).
2. `proxy.mp4` + `audio.wav` (16 kHz mono) - ffmpeg; everything downstream reads these.
3. `transcript.json` - words with start/end/confidence, segments, speakers. Fast pass: `yap --json --word-timestamps`; precise pass: WhisperKit CLI + SpeakerKit; optional cloud fallback. Also emit `transcript.srt`.
4. `silence.json` - ffmpeg `silencedetect` (e.g. `-30dB`, `d=0.35`) and/or auto-editor `--export json` speech/non-speech ranges.
5. `shots.json` - PySceneDetect AdaptiveDetector (+TransNetV2 for dissolves); per-shot midpoint frame extracted to `frames/shot_NNN.jpg` at 720p.
6. `frames.index` - SigLIP 2 embeddings for shot keyframes (and 1 fps for screen recordings) in a small vector store (sqlite + numpy or LanceDB) for `find_frames("person holding coffee")`.
7. `faces.json` / `objects.json` - Apple Vision faces per keyframe (bbox, track ids by IoU); RF-DETR objects when needed. Feeds auto-reframe and zoom/pan targets.
8. `ocr.json` - Apple Vision text per keyframe for screen recordings (window titles, error strings, URLs) -> lets the agent say "cut to where the terminal shows the stack trace".
9. `audio_features.json` - loudness (loudnorm pass-1 JSON), RMS envelope, laughter/applause candidates (energy + transcript cues), madmom beats/downbeats for any music track.
10. `descriptions.json` - VLM captions: local Qwen3-VL for every shot (cheap, private), Gemini agentic mode for a whole-file narrative summary when the user opts into cloud, Claude vision for high-stakes shot selection using contact sheets.
11. `moments.json` - LLM-derived structured highlights: `{start,end,type:[hook|punchline|demo|reaction|silence|filler],score,evidence}` combining transcript, energy, faces, shots.

Everything is idempotent and content-addressed so re-runs are free and the agent can request deeper analysis (`analyze(media, level="deep")`) on demand.

## 7. Recommended agent-callable tools

Keep them coarse, typed (JSON schema), validated, and receipt-producing (kinocut's pattern). Suggested set:

**Senses**
- `list_media()`, `get_media_info(id)`
- `get_transcript(id, {speaker?, range?})`, `search_transcript(query|regex, ids?)` (Videogrep-style)
- `get_shots(id)`, `get_silences(id, threshold?)`, `get_moments(id, type?)`
- `find_frames(query, ids?, k)` (SigLIP), `describe_range(id, start, end, detail)` (VLM), `look_at(id, timestamps[])` (returns contact sheet to the LLM's own vision)
- `get_faces(id, range)`, `get_ocr(id, range, query?)`, `get_beats(audio_id)`, `measure_loudness(id)`

**Hands (timeline is the source of truth; render is separate)**
- `create_timeline(fps, aspect)`, `add_clip(media, in, out, track, at?)`, `remove_range`, `split`, `ripple_delete_silences(track, min_gap, padding)`
- `add_captions(style, source=transcript, range?, word_highlight?)`, `add_text(text, style, in, out)`, `add_zoom_pan(clip, keyframes|target="face"|"cursor")`, `add_transition(type, at, duration)`
- `add_broll(query|asset_id, in, out, source=[pexels|pixabay|user])`, `add_meme(query, in, out, source=klipy|giphy)`, `add_sfx(query, at)`, `add_music(query|asset, in, out, duck_under_speech=true, sync_cuts_to_beats?)`
- `generate_tts(text, voice, provider=kokoro|elevenlabs|openai|apple)`, `generate_image(prompt, size, provider=drawthings|flux|gpt-image)`, `generate_video_clip(prompt, seconds, provider)` (opt-in, cost-gated)
- `normalize_audio(target_lufs=-14)`, `validate_timeline()`, `render_preview(range, low_res)`, `export(preset, path)`, `export_nle(format=fcpxml|premiere|resolve)`

Each tool returns a receipt `{tool, args, outputs, hashes, duration_ms, warnings}` and the preview tools return images the agent can inspect, so the loop is: sense -> plan -> act -> look -> revise.
