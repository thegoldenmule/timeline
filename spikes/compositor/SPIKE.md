# Spike: one custom `AVVideoCompositing` for preview, frame grabs, and export

Date: 2026-09-08. Machine: macOS 26.3, Apple M4 Max, Xcode 26.6, Swift 6.3.3, SwiftPM only (no Xcode project).
Code: `Package.swift` + 5 files in `Sources/CompositorSpike/`, 507 lines total. Run with
`swift run CompositorSpike "$PWD"` from this directory (writes media to `./tmp/`). Set `SPIKE_NO_CM=1` to
disable Core Image colour management for comparison (two assertions then fail by design, see below).

## Verdict

**Assumption validated.** A single `AVVideoCompositing` class (`SpikeCompositor`, Core Image on a Metal-backed
`CIContext`) set once via `customVideoCompositorClass` served all three consumers unchanged, and did the
crossfade, PiP transform (scale/position/opacity), and a Core Text caption with a 300 ms scale-in animation in
one `startRequest` code path, with no `AVVideoCompositionCoreAnimationTool`. 32 programmatic pixel/frame
assertions pass across `AVAssetImageGenerator`, `AVAssetExportSession` (H.264 720p and HEVC), and a headless
`AVPlayerItem` + `AVPlayerItemVideoOutput`. Frame-accurate seeking (zero tolerance) was verified by decoding a
16-bit barcode drawn per source frame: every seek returned exactly the requested frame.

One real gotcha was found (colour: untagged BGRA source frames shift pure green by ~10%); it is not a blocker
for the architecture but must be resolved before the compositor is trusted for colour-critical output.

## What was built

1. **Synthetic media** (`Media.swift`): `AVAssetWriter` + `AVAssetWriterInputPixelBufferAdaptor` (32BGRA in,
   H.264 out) and an AAC audio input fed LPCM Float32 `CMSampleBuffer`s built with
   `CMAudioFormatDescriptionCreate` / `CMBlockBufferCreateWithMemoryBlock` / `CMSampleBufferCreate`.
   Three 4 s 1280x720 30 fps clips: red/440 Hz, green/880 Hz, blue/1320 Hz. Each frame carries a 16-bit
   frame-counter barcode across the top (32 px per bit, 24 px tall). All three clips: 875 ms to write.
2. **Declarative model** (`Model.swift`): `RTime {value, timescale}`, `Clip {url, timelineStart, sourceIn/Out,
   transform?, crossfadeFromPrevious?}`, `Transform {scale, center, opacity}`, `Caption {text, start, end,
   scaleInMs}`, `Timeline`.
3. **Compiler** (`compile(_:)`): `AVMutableComposition` with two video tracks (IDs 1/2, full-frame clips
   alternate; PiP takes the free track) and two audio tracks (3/4) with `AVMutableAudioMixInputParameters
   .setVolumeRamp(fromStartVolume:toEndVolume:timeRange:)` for the crossfade and `setVolume(_:at:)` to duck the
   PiP. Instructions are generated by cutting the timeline at every clip/crossfade/caption boundary; each
   `SpikeInstruction: NSObject, AVVideoCompositionInstructionProtocol` carries `base`, `crossfadeTo`, `pip`,
   `caption` and sets `requiredSourceTrackIDs`, `containsTweening`, `passthroughTrackID = kCMPersistentTrackID_Invalid`.
   Timeline under test: red 0-4 s; green 3-7 s (1 s crossfade); blue PiP 4.5-6.5 s (source 1-3 s, scale 0.4,
   center (984,224), opacity 0.8); caption "Hello, compositor!" 1.0-2.5 s. 7 instructions, no gaps.
4. **Compositor** (`Compositor.swift`, 97 lines): `startRequest(_:)` fetches frames with
   `request.sourceFrame(byTrackID:)`, wraps them in `CIImage(cvPixelBuffer:)`, crossfades with
   `CIFilter.dissolveTransition()` (`import CoreImage.CIFilterBuiltins`) using progress derived from
   `request.compositionTime` and the instruction's `timeRange`, transforms the PiP with a `CGAffineTransform`
   (y flipped: model is top-left, CI is bottom-left) and applies opacity via `CIColorMatrix` `inputAVector`,
   renders the caption with `CTFontCreateWithName` / `CFAttributedStringCreate` / `CTLineCreateWithAttributedString`
   / `CTLineDraw` into a `CGContext` -> `CGImage` -> `CIImage` (cached per text under an `OSAllocatedUnfairLock`),
   eases the scale-in (ease-out cubic over 300 ms), then `request.renderContext.newPixelBuffer()`,
   `CIContext.render(_:to:bounds:colorSpace:)`, `request.finish(withComposedVideoFrame:)`.
   Declared: `sourcePixelBufferAttributes` and `requiredPixelBufferAttributesForRenderContext` = 32BGRA,
   `supportsWideColorSourceFrames = true`, `supportsHDRSourceFrames = true`, `canConformColorOfSourceFrames = true`.
5. **Consumers** (`Consumers.swift`): see results.

|---|---|---|---|

| 5.5 s | PiP rect mean ~ 0.8 blue over green | (2,124,227) | (2,134,228) |
| 5.5 s | background still green (R<40, G>200, B<60) | (0,231,40) | (1,232,41) |
| 5.5 s | green clip barcode == 75 (full-frame strip intact next to PiP) | 75 | 75 |
| 1.5 s | caption region differs from red bg | (241,80,0) | (240,82,0) |
| 1.033 s | caption still scaling in (less coverage than at 1.5 s) | (251,11,0) | (249,12,0) |

Player path: seeks listed above, plus center colour at each seek matched the expected clip.

Note on the crossfade/PiP values: Core Image blends in **linear light** (working space linear sRGB). A 50/50
dissolve of pure red and pure green therefore reads (188,188,0) in sRGB, not the (128,128,0) a gamma-space
NLE would produce; 0.8 blue over green reads (0,124,231) rather than (0,51,204). With `SPIKE_NO_CM=1`
(`CIContext` `.workingColorSpace: NSNull()`) the same frames read (139,139,0) and (2,59,206), i.e. gamma-space.
Which one is "right" is a product decision (Final Cut/Premiere default to gamma-space dissolves); the spike
defaults to CI's linear behaviour and asserts on that.

## Gotchas hit

1. **`.macOS(.v26)` does not exist in `swift-tools-version: 6.0`** -- use `.macOS("26.0")`.
2. **`AVMutableVideoComposition`, `AVMutableVideoCompositionInstruction`, `AVMutableVideoCompositionLayerInstruction`
   are deprecated in macOS 26** in favour of value-type configurations: `AVVideoComposition.Configuration`
   (Sendable struct; `init(animationTool:colorPrimaries:colorTransferFunction:colorYCbCrMatrix:
   customVideoCompositorClass:frameDuration:instructions:outputBufferDescription:perFrameHDRDisplayMetadataPolicy:
   renderScale:renderSize:sourceSampleDataTrackIDs:sourceTrackIDForFrameTiming:spatialVideoConfigurations:)`)
   and `AVVideoComposition(configuration:)`. The deprecated class still works (used here for speed); the real
   implementation should use `Configuration`. `AVVideoCompositionCoreAnimationTool` is also on the deprecation
   path (`API_TO_BE_DEPRECATED`) -- one more reason to avoid it.
3. **Swift 6 concurrency**: AVFoundation instantiates the compositor itself and calls `startRequest` on its own
   serial queue (`...clientcustomcompositorq`), never on the main actor. The class must be
   `final class X: NSObject, AVVideoCompositing, @unchecked Sendable`; mutable state (caption cache) is guarded
   with `OSAllocatedUnfairLock`. The instruction class likewise needs `@unchecked Sendable` (the protocol is
   used in `[any AVVideoCompositionInstructionProtocol]` arrays that cross isolation). Attribute dictionaries
   are typed `[String: any Sendable]`. Static instrumentation counters needed `nonisolated(unsafe)`.
   No retain cycles observed: the compositor holds nothing back-referencing the request or render context.
4. **`renderContextChanged` fires once per consumer session** (4 per run). Anything sized to the render context
   (pools, intermediate textures) must be rebuilt there; this spike allocates per request so ignored it.
5. **Colour: source frames arrive as untagged 32BGRA** (`ColorPrimaries`/`TransferFunction`/`YCbCrMatrix`
   attachments all nil, before and after setting `colorPrimaries/colorTransferFunction/colorYCbCrMatrix =
   ITU_R_709_2` on the video composition, which also did not tag the render-context buffers). Pure green
   (0,255,0) in the source decodes to (0,255,0) via a plain `AVAssetImageGenerator` (colour space
   `kCGColorSpaceCoreMedia709`), but through the compositor it becomes (0,231,40) in both the composition and
   the export, and (0,220,37) with CI colour management off -- so the shift is in AVFoundation's YUV->BGRA
   conversion for the compositor's requested format (probably a 601/709 matrix assumption on untagged buffers),
   not in Core Image. Red is unaffected (saturated). **Next step**: request native YUV sources
   (`kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange`/`FullRange`) in `sourcePixelBufferAttributes` and let CI
   do the matrix, or tag buffers explicitly with `CVBufferSetAttachment` before wrapping them.
6. **A temporary `AVAssetImageGenerator` hung the process**: `try await AVAssetImageGenerator(asset:).image(at:)`
   with the generator as an unnamed temporary never returned (the request was cancelled on dealloc without
   completing). Binding the generator to a `let` fixed it. Keep generators alive for the whole request.
7. **stdout is fully buffered when piped**; with a hang this hides all progress. `setvbuf(stdout, nil, _IOLBF, 0)`.
8. **Core Text without AppKit**: in a pure Foundation/CoreText target, `NSAttributedString.Key.font` does not
   exist; use `kCTFontAttributeName`/`kCTForegroundColorAttributeName` with `CFAttributedStringCreate`.
9. **Coordinate flip**: the model uses top-left origin; CI/CG use bottom-left. Both the PiP translation and the
   caption placement needed `size.height - y`.
10. **Barcode strip during a crossfade is a blend of two frame counters** and decodes to garbage (111); frame
    accuracy can only be asserted where one full-frame clip is opaque. The PiP region does not cover the strip,
    so 5.5 s was verifiable.

## HDR / 10-bit

`supportsHDRSourceFrames`, `supportsWideColorSourceFrames`, and `canConformColorOfSourceFrames` compile and are
declared `true`. A pixel-format attribute dictionary listing `kCVPixelFormatType_420YpCbCr10BiPlanarVideoRange`
(`x420`, 2016686640), `kCVPixelFormatType_4444AYpCbCr16` and `kCVPixelFormatType_64RGBAHalf` compiles and is
printed at runtime; it is **not** what the compositor actually declares (BGRA8 is) and was not exercised with
HDR media. `AVVideoComposition.Configuration.perFrameHDRDisplayMetadataPolicy` and `outputBufferDescription:
[[CMTag]]` exist in the macOS 26 API surface for the real implementation.

## Not verified

- HDR / 10-bit / wide-colour rendering with real HDR media (only compiled and declared).
- Behaviour with a real on-screen `AVPlayerLayer`/`AVPlayerView` (headless output was sufficient to prove
  frame accuracy and real-time rendering; on-screen was out of scope).
- Audio: the `AVMutableAudioMix` ramps were attached to both the export and the player but the mixed audio
  was not decoded and inspected.
- Long timelines / memory behaviour / `cancelAllPendingVideoCompositionRequests` under scrubbing load.
- Release-build performance (all numbers are from a debug build).
- The colour shift's root cause (see gotcha 5) -- identified and localised, not fixed.
- `AVVideoComposition.Configuration` (the non-deprecated API) was inspected in the Swift interface but the
  spike uses the deprecated mutable class.
